STEP 1: LOCAL REPOSITORY SETUP
----------------------------------------------------------------------
git --version
    Shows the installed Git version, confirming Git is available.

mkdir git-workflow-assignment && cd git-workflow-assignment
    Creates the project folder and moves into it (shell commands).

git init -b main
    Initialises an empty Git repository in the current folder and names
    the default branch "main".

git config user.name "Saniya Patil"
git config user.email "saniyagranger66@gmail.com"
    Sets the author name and email recorded on commits in this repository.

git status
    Shows which files are untracked, modified or staged.

STEP 2: GIT WORKFLOW EXECUTION
----------------------------------------------------------------------
git add index.html about.html
    Stages the two files so they are included in the next commit.

git commit -m "Initial commit: add index.html and about.html"
    Records the staged files as the first snapshot of the project.

git diff
    Shows the line-by-line changes made since the last commit (unstaged).

git add index.html
git commit -m "Update index.html: add navigation bar and welcome section"
    Stages the modified index.html and records it as the second commit.

git branch feature
    Creates a new branch named "feature" pointing at the current commit.

git branch
    Lists all local branches; the current one is marked with *.

git switch feature
    Moves HEAD to the feature branch (older equivalent: git checkout feature).

git add about.html
git commit -m "Add skills section to about page (feature branch)"
    Commits the about.html change on the feature branch only.

git switch main
    Switches back to the main branch.

git merge --no-ff feature -m "Merge branch feature into main"
    Merges feature into main; --no-ff forces a merge commit so the branch
    activity remains visible in the history.

git log --oneline --graph --all
    Shows a compact graph of every commit on all branches.

git log
    Shows the full commit history with hash, author, date and message.

STEP 3: .gitignore IMPLEMENTATION
----------------------------------------------------------------------
cat .gitignore
    Displays the ignore rules: "*.log" (all log files) and "temp/" (folder).

git status --ignored
    Lists ignored files too, proving debug.log and temp/ are ignored.

git check-ignore -v debug.log temp/notes.txt
    Shows which .gitignore rule causes each file to be ignored.

git add .gitignore
git commit -m "Add .gitignore to ignore .log files and temp/ folder"
    Commits the .gitignore file so the rules are shared with the repository.

STEP 4: UNDO OPERATION
----------------------------------------------------------------------
git add contact.html
git commit -m "Add contact page"
    Makes an additional commit that will be undone.

git log --oneline -3
    Shows the last three commits, confirming the new commit exists.

git revert --no-edit HEAD
    Undoes the last commit by creating a new commit with the opposite
    changes. History is kept, which makes it safe for pushed branches and
    lets GitHub show the undo. (Alternative: git reset --hard HEAD~1 removes
    the commit entirely, but rewrites history.)

git show --stat HEAD
    Shows the revert commit and the file it removed (contact.html).

ls
    Confirms contact.html no longer exists in the working directory.

STEP 5: GITHUB INTEGRATION
----------------------------------------------------------------------
(Public repository "git-workflow-assignment" created on GitHub, empty,
 with no README, so the local history can be pushed as-is.)

git remote add origin https://github.com/Saniya1613/git-workflow-assignment.git
    Links the local repository to the GitHub repository under the name "origin".

git remote -v
    Verifies the fetch and push URLs of the remote.

git push -u origin main
    Uploads the main branch and sets origin/main as its upstream.

git push -u origin feature
    Uploads the feature branch so the branch also appears on GitHub.
